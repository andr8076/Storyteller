# Development status

## Current objective
Connect the corrected experimental ledger views to opt-in retrieval, with explicit precedence for newer Normal Texting memory.

## Verified implementation
- Normal Texting retrieves character knowledge and historical events from per-project, cited SQLite indexes. Earlier beliefs are available for explicit historical questions; ordinary requests prefer current state. Profiles and event sources remain human-readable.
- Catch Up records chronological attributed perspectives and advances continuation after completion. Data Dump records timeless reference knowledge without advancing chronology. Neither sends captured text to the creative model.
- Normal prompts select memory before asynchronously analyzing the latest author message, preventing same-request reinjection. Per-project response learning OFF persists.
- An optional dedicated local perspective model supplements the 2B worker for dense dialogue in Catch Up and Normal Texting (author messages and generated scenes), with source validation and fallback on failure. It runs in the background worker after the outgoing memory snapshot.
- The control panel can persistently enable this optional model with K and a local GGUF path. On the next manual Storyteller start, the same session launches the local CPU server on 18986 and closes it on stop; the 2B worker remains the fallback. No login service or external model is introduced.
- Truncated large import responses split numbered sections into smaller model calls and retain original citations; identity proposals describing transient actions are rejected.

## Architecture decision and limitations
- `narrative_projection.py` now derives current/historical views from validated propositions, independent of model topic labels. A later supported observation of explicit negation supersedes the earlier proposition and exposes a link plus reason; the database history is unchanged. Unrelated facts sharing a topic remain current. Equal-order observations, other characters, and tentative contradictory claims cannot retract knowledge. Reconciliation handles equivalent copular statements and explicit negation, not arbitrary semantic opposites, implied corrections, or aliases.
- Perspective merging now preserves word order, negation, and spatial qualifiers and selects a complete validated statement over its equivalent fragment. Replaying the captured 9B output through Catch Up retains all 6 episodes, replaces Oren's fragment with "The flute was inside the cedar cabinet", preserves the source, and passes the formerly failing explicit-correction probe. 77 tests pass locally, including temporal history and non-merging regressions; no new model inference or Build-Arch access was used for this change. Ledger retrieval remains disconnected from the gateway.
- Experimental `narrative_ledger.py` accepts one local-model episode proposal format, validates exact numbered source spans, and writes idempotent append-only records plus a readable Markdown audit trail inside an isolated project. Actions, assertions, beliefs and observations remain distinct; current/historical views derive from the event history. The existing literal fallback retained only Joss's final observation in a deception scene. Live 9B generated four episode kinds in 43.32 seconds, initially accepted only as one assertion because the model omitted certainty and used verb phrases. A witness scene took 33.53 seconds and missed Mira; one explicit witness instruction elicited her observation in 40.59 seconds but still omitted topics and mis-cited a linked belief. The parser now completes verb phrases only when the named actor's source clause supports them, infers certainty from explicit belief cues, and links a belief to exactly one supported speaker assertion. Replaying the *captured* live output accepted 4/4 deception records (Joss history 2) and 3/3 initial witness records (Joss history 1), versus one literal perspective each. The state validator excludes quoted speech from world truth; narrator state remains accepted. The opt-in Catch Up shadow path writes episodes after a successfully committed section, never affecting canon or retrieval. An unavailable shadow model leaves Catch Up complete. The path also incorporates existing validated perspectives to recover missed witnesses or beliefs without a further model call. 72 local tests pass. No migration was performed.

- The append-only knowledge ledger adapts the temporal and provenance idea seen in Narra without adopting its entire database and embedding stack. Other frameworks may still offer advantages.
- 9B improves explicit belief tracking on the two tested scenes, but adds latency and still proposes unsupported claims; keep it optional until a broader quality/cost comparison.
- Extraction can miss indirect or pronoun-heavy information. Retrieval is largely lexical. The full Sparkdrive manuscript and long-running Jan project behavior remain untested.
