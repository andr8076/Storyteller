# Development status

## Current objective
Improve source-backed character knowledge chronology across dialogue, pronouns, import, and retrieval.

## Verified implementation
- The Jan gateway, import modes, and memory worker remain in place. No runtime or project migration was performed.
- Profile retrieval now scores both filenames and contents. Long profiles inject matching lines from anywhere in the file, bounded by the existing per-file and total context limits.
- Baseline before this change: 14 unit tests passed. After this change: 16 passed (`python -m unittest discover -s tests -v`). A disposable-world test covers a fact after the former 1,900-character cutoff and project isolation.
- Experimental character knowledge ledger: Catch Up and completed generated scenes can record explicit named perspectives from the existing extraction call. Each state retains its source sentence and source ID, preserves certainty history, survives retries, and exports current state to `character-knowledge.md`. Normal Texting retrieves relevant attributed states. Data Dump remains timeless and does not advance this chronological ledger.
- Comparative fixture: the old canon extractor incorrectly accepted an explicitly suspected vault location as world fact; now it rejects it while recording Ivo's suspicion, then updates Ivo's current state when he discovers the location. Historical states remain in SQLite. A focused topic reconciliation step links obvious alternate labels without merging different propositions. Data Dump saves timeless baseline perspectives. An additive migration preserves the first experimental schema.
- Build-Arch Qwen3.5-2B probe (three one-sentence cases, isolated temp project): joint prompt produced no suspicion, one correct discovery, no mistaken belief (1/3). A more explicit prompt recovered suspicion but omitted discovery and reversed the mistaken belief; a dedicated prompt did no better. Added source-clause validation and narrow literal fallback for explicit named mental verbs. A second real-model run saved all three short cases. A multi-sentence scene exposed model phrasing errors; the literal fallback now keeps the proposition and chronology. An isolated real-model Catch Up completed, advanced the continuation point, left the original text untouched, and stored current Nera/Olin perspectives. The actual HTTP gateway sent those attributed perspectives to a local mock writing endpoint. The import also misclassified “Nera confirmed…” as identity; the latest validator rejects mental-state reports outside the event category. A final Qwen Catch Up run verified the current Nera/Olin states and no erroneous Nera identity profile. 28 unit tests pass.

## Findings and decisions
- The old gateway matched profile filenames only and injected their initial 1,900 characters. A correctly stored late fact could be invisible to the writer.
- Narra is MIT licensed and offers structured character knowledge, events, relationships, and local semantic search. Its Rust, SurrealDB/RocksDB, and embedding stack would introduce a second memory store and integration work. No evidence yet shows it improves Storyteller's current extraction or retrieval enough to justify migration. Its knowledge ledger and temporal concepts remain candidates for a small later experiment.
- Adapted Narra's append-only certainty/provenance idea into an isolated Storyteller ledger. This avoids a premature wholesale migration while exercising a substantive capability. Narra's richer graph, temporal event queries, and semantic search remain open for comparison.
- LoreGraph's entity resolution uses cheap candidate blocking followed by model judgment and a sanity pass. Topic reconciliation currently applies only its conservative blocking idea: near-identical topic words, or identical fact text with a shared topic anchor. Ambiguous or semantic-only matches remain separate pending local-model evaluation.
- This change introduces no model calls, migrations, or new Python packages. It reads eligible profile files per request; performance on very large profile collections has not been measured.

## Known limits
- The model-backed probe exercised Qwen, Catch Up, and the actual gateway HTTP handler with a mock writer in an isolated temporary project. Jan/Cydonia and Sparkdrive have not been exercised. No personal projects or original manuscripts were modified.
- Dialogue/pronoun probe on Build-Arch: Qwen3.5-2B returned no knowledge for two short prose scenes. The literal fallback incorrectly saved “Dorian believed her and searched…” as a belief about “her,” and included Cyra's clause in Ari's suspicion. It now skips pronoun-only propositions and cuts at contrasting clauses.
- Existing Qwen3.5-9B-Q4_K_M on CPU: joint prompt found Ari/Cyra but prematurely assigned Dorian the true location. A dedicated perspective-only prompt produced the correct raw belief sequence in two unrelated scenes with Storyteller's own sentence numbering (about 10.7 and 14.8 seconds per call). The validator accepts both Joss states in the map scene and Dorian's earlier attic belief; it rejects Lena's implicit knowledge and Dorian's later pronoun-only discovery in the key scene. The model is more capable but an automatic switch would add substantial latency and still leave pronoun attribution unresolved.
- The knowledge validator no longer applies the world-fact observer guard when a character explicitly sees something and gains knowledge. 30 unit tests pass in the development checkout.
- The current change binds a nearby pronoun discovery to a uniquely named preceding subject, checks fact content against the cited clause, and sorts states by source sentence before recording. The combination step retains later model-derived states after an earlier literal state for the same topic. A fixture based on the local 9B model's actual key-scene output rejects an inferred Lena state, records Dorian's attic belief and later cellar discovery, and retrieves only his current knowledge. Ambiguous antecedents are rejected. 19 focused tests pass.
- Retrieval remains lexical; paraphrases without overlapping terms can be missed. Canon, summary, and source excerpts still use their existing ranking and truncation rules.
- Existing tests do not yet cover the full gateway and import path.
- Existing completed imports are not backfilled into the new knowledge ledger; their original sources remain intact. The current grouping uses model-proposed topic strings, so paraphrased topics may form separate histories until entity/topic reconciliation improves.
- Qwen3.5-2B is unreliable for perspective extraction from short isolated sentences. Literal fallback covers simple declarative constructions, while complex dialogue, pronouns, and indirect knowledge still depend on model quality.
- The adjacent pronoun rule only handles a clearly named prior subject and an immediate discovery sentence. More complex dialogue and cross-section antecedents remain unresolved. The earlier 9B output was reused as a deterministic fixture; this change has not yet been rerun through a live 9B import.
- Relevant commits: `30a49ff` profile retrieval; `be11f47` append-only knowledge experiment; `dd2fcfe` topic reconciliation. Data Dump baseline support is the current work.
